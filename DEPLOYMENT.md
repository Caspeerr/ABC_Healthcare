# ABC Healthcare deployment

This version uses the existing AWS credentials stored in GitHub Actions Secrets.

Required GitHub repository secrets:
- AWS_ACCESS_KEY_ID
- AWS_SECRET_ACCESS_KEY
- VPC_ID (your existing default VPC ID, e.g. `vpc-xxxxxxxxxxxxxxxxx`)
- SUBNET_IDS (JSON array of 3 subnet IDs, e.g. `["subnet-aaa","subnet-bbb","subnet-ccc"]`)
- EC2_SUBNET_ID (one of the three above - where the backend EC2 instance launches)

The last three feed `terraform.tfvars`-equivalent values into CI via
`TF_VAR_*` environment variables, since real subnet/VPC IDs are
intentionally not committed to this repo (see terraform.tfvars.example
for local development).

No AWS CLI credentials are required on the local computer.

## Existing default VPC

Region: ap-south-1

This project deploys into the account's existing default VPC and its
existing subnets rather than creating new networking. The actual VPC
ID and subnet IDs are account-specific, so they are not committed to
this repo - set them in a local `terraform.tfvars` (copy
`terraform/terraform.tfvars.example` and fill in your own values from
VPC -> Your VPCs / VPC -> Subnets in the AWS Console).

Terraform only reads/uses these resources. It does not create or destroy the default VPC.

## Architecture

Browser -> CloudFront -> private S3 React frontend
                     |
                     +-- /api/* -> ALB -> EC2 Node.js -> RDS MySQL

EC2 administration is through SSM Session Manager. Port 22 is not opened.

RDS credentials are generated by Terraform and stored in Secrets Manager. The EC2 IAM role can read only this secret.

## GitHub Actions

Actions -> Deploy ABC Healthcare -> Run workflow

The deployment workflow:
1. Creates/updates infrastructure with Terraform.
2. Builds the React frontend.
3. Uploads the frontend to the private S3 bucket.
4. Packages the backend.
5. Uploads the backend artifact to a private deployment bucket.
6. Waits for SSM.
7. Uses SSM Run Command to install/deploy the backend.
8. Initializes the RDS schema.
9. Restarts the Node.js service.
10. Prints the CloudFront URL.

Destroy:
Actions -> Destroy ABC Healthcare -> Run workflow

This destroys resources managed by this Terraform state. The default VPC and its existing networking are not managed by Terraform and remain.

## Terraform state

GitHub-hosted runners are ephemeral, so Terraform state is stored in:
abc-healthcare-sambrid-tfstate / abc-healthcare/terraform.tfstate

The workflows bootstrap this state bucket automatically using the existing GitHub AWS Secrets credentials. The state bucket is intentionally not destroyed by the project destroy workflow because it contains the Terraform state required to track infrastructure.

Do not commit .env files or Terraform state files.
